1. PRODUCT IDENTITY AND USERS
================================================================================

Name: DKSK Official — Painting Contractor Management System
Short brand in UI: "DKSK"
Audience: Internal staff of a painting contractor business (DKSK Official).

Primary goals:
  - Record work orders and convert them into draft invoices, then submit invoices.
  - Track client companies, properties, supervisors, and subcontractors.
  - Manage a catalog of job types with bedroom/bathroom sizes and prices.
  - Run finance views: accounts receivable, aging, sales, payroll, contractor jobs.
  - Export filtered data to PDF and Excel.
  - Backup/restore the SQLite database and import master data from CSV.
  - Optionally auto-update the desktop app from GitHub releases.

The app is a single-user desktop experience (no multi-user auth in UI). Company
profile ("My Company Info") appears on home/dashboard and in exported reports.

  - Top bar within sidebar: navbar-dark, brand link "DKSK" with Radzen "apps" icon.
  - Nav links: white/light text, Radzen icons per item, Bootstrap nav-link styling.
  - Section headers in sidebar (uppercase, small, text-white-50):

  - Context block at top of nav (small, text-white-50):
      "Current Section: {GlobalState.CurrentSection}"
      "Company: {GlobalState.CurrentCompanyInfo.Name}" when profile loaded.

3.3 Main content area
  - Page titles: centered h3 with Radzen icon + descriptive title (e.g. "Start Job").
  - Forms use Bootstrap grid (container, row, col-md-*), RadzenStack where noted.

  - Modals: Radzen DialogService (confirmation, item picker, invoice confirm).

  - Font family: 'Helvetica Neue', Helvetica, Arial, sans-serif.
  - Links / btn-link: #006bb7.

3.5 Global state (in-memory, session)
  GlobalStateService holds:
    - CurrentCompanyInfo (MyCompanyInfo, from DB)
    - CurrentSection (string label shown in sidebar)
  Pages call SetCurrentSection on load. OnChange event refreshes NavMenu.

  Exact section labels set per page (others inherit the previously set value):
    Home (/)                          → "Dashboard"
    /startjob, /activejobs            → "Operations"
    /createinvoice                    → "Billing"

3.6 Client-side persistence (localStorage)
  - Accounts Receivable persists user-reordered grid columns under the key
    "AccountReceivableColumnOrder" (comma-separated column titles). On load,
    the grid restores the saved order if present.
  - Preferences.LastBackupDirectory remembers the last folder used for Quick
    Backup (MAUI Preferences, not localStorage).

3.7 Result pattern (all workflows)
  OperationResult { bool Success; string Message; }
  OperationResult<T> { T? Data; } inherits Success/Message.
  UI maps Success → green notification; Failure → red with Message text.

5. DATA MODEL (DATABASE SCHEMA AND RELATIONSHIPS)
================================================================================

Engine: SQLite. Single file app.db under user app data folder.

Entity: MyCompanyInfo (singleton business profile for DKSK)
  Id (PK, identity)
  Name          required, max 100
  Phone         required, [Phone] validator, max 20
  Email         required, [EmailAddress] validator, max 100
  Address       required, max 200
  Zip           required, max 10
  LicenseNumber required, max 50

Entity: Company (table name "Company")
  Id (PK, identity)
  CompanyID    required int, [Range 1000–9999], unique DB index
  Name         required, max 100
  Owner        optional, max 100
  Phone        optional, [Phone] validator, max 20
  Email        optional, [EmailAddress] validator, max 100
  Address      optional, max 200
  City         optional, max 50
  Zip          optional, max 10
  SpecialNote  optional, max 500
  Navigation:  List<Supervisor> Supervisors

Entity: Supervisor
  Id (PK, identity)
  Name (required string), Phone (optional), Email (optional)
  CompanyId (FK → Company.Id), CASCADE delete
  Navigation: parent Company [Required, JsonIgnore], List<Properties> Properties

Entity: Properties (property/site under a supervisor)
  Id (PK, identity)
  Name (string, default ""), Address, City, Zip (all optional)
  GateCode, GarageRemoteCode, LockBox, SpecialNote (optional)
  ManagerName, ManagerPhone, ManagerEmail (optional)
  IsActive (bool?)
  SupervisorId (FK → Supervisor.Id), CASCADE delete
  Navigation: Supervisor Supervisor [Required, JsonIgnore] — JsonIgnore on the
  back-reference prevents cycles in JSON backup/restore.

Entity: Contractor
  Id (PK, identity)
  Name              required, max 100, unique by exact name on save
  LicenseNumber     optional, max 50
  SocialSecurityNumber  optional, max 20
  ContractorID      optional string, max 50  (free-form business identifier)
  PayrollPercent    optional string, max 10
  CellPhone         optional, [Phone] validator, max 20
  Email             optional, [EmailAddress] validator, max 100
  Address           optional, max 200
  City              optional, max 50
  Zip               optional, max 10
  SpecialNote       optional, max 500
  IsActive          bool?  — only active contractors appear in invoice contractor lists

Entity: JobDescription (table "JobDescription"; global alias JobDescriptionModel)
  Id (PK, identity)
  description (string, default ""), sizeBedroom (int), sizeBathroom (int),
  price (int)
  NotMapped + JsonIgnored aliases Description / SizeBedroom / SizeBathroom /
  Price route to the lowercase backing fields for code that prefers PascalCase.

Entity: Invoice
  Id (PK, identity)
  TodaysDate      required, not MinValue
  WorkDate        required, not MinValue
  CompanyName     required, max 100
  PropertyAddress required, max 200
  Unit            required, max 50
  GateCode        optional, max 50
  LockBox         optional, max 50
  SizeBedroom     [Range 0..20]
  SizeBathroom    [Range 0..20]
  WorkOrder       optional, max 100
  JobDescriptionChoice  required string — JSON array of selected job
                  description names (catalog "description" values)
  ContractorName  required, max 100  (drafts created by Start Job use "N/A")
  AmountCost      int, [Range 0..int.MaxValue]
  AmountPaid1     int, [Range 0..int.MaxValue]
  DatePaid1       DateTime
  CheckNumber1    optional, max 100
  AmountPaid2     int, [Range 0..int.MaxValue]
  DatePaid2       DateTime
  CheckNumber2    optional, max 100
  InvoiceCreatedDate  DateTime? — set when Status moves to Submitted
  SpecialNote     optional, max 1000
  GarageRemoteCode optional, max 50
  Status          int (maps to InvoiceStatus enum; see §6)
  IValidatableObject.Validate enforces:
    - TodaysDate / WorkDate not MinValue
    - AmountPaid1 + AmountPaid2 ≤ AmountCost
      (error: "Combined paid amount cannot be greater than amount cost.")

Helper type Payment { DateTime Date; int Amount; string CheckNumber; } exists
in Invoice.cs but is not persisted and is not currently used by the UI; safe
to omit in a re-implementation.

Relationships:
  Company 1—* Supervisor 1—* Properties (cascade deletes)
  Invoice is denormalized (stores CompanyName/PropertyAddress strings, not FKs)

Invoice display number (UI convention, not stored):
  DisplayInvoiceNumber = Invoice.Id + 10000 (string)

6. INVOICE LIFECYCLE AND STATUS MACHINE
================================================================================

enum InvoiceStatus:
  Draft = 0      — work order / draft invoice, not yet finalized for billing
  Submitted = 1  — finalized invoice (sales); InvoiceCreatedDate set
  Paid = 2       — (enum exists; primary filtering uses payment amounts)

Query definitions (must match exactly):
  Active jobs list:     Status == Draft
  Create invoice search: Status == Draft, filtered by WorkDate range
  Sales list:           Status == Submitted
  Accounts receivable:  AmountCost > (AmountPaid1 + AmountPaid2)  [any status]
  Aging reports:        derived from receivable + date logic (see page spec)

Typical flow:
  1. Start Job → builds draft Invoice in memory → confirm dialog → persist as Draft
  2. Create Invoice → find Drafts in date range → user selects row → confirm dialog
     → assign contractor, job lines → Submit → Status Submitted, recalc AmountCost
  3. Accounts Receivable → record payments on selected rows → update DB
  4. Sales / Active Jobs / Payroll → read-only grids with filters + export

AmountCost calculation (whenever job lines matter):
  JobDescriptionChoice is JSON list of strings (job catalog description names).
  Sum JobDescription.price for each name that exists in catalog.
  If JSON invalid/empty → AmountCost 0.

7. CORE BUSINESS RULES AND CALCULATIONS
================================================================================

7.1 Company
  - CompanyID must be unique (DB unique index).
  - On create: duplicate Name or CompanyID rejected with user message.
  - EnsureCompanyByName: trim name; if exists return it; else allocate new CompanyID
    in range 1000–9999 (scan for next free); fail if range exhausted.
  - Delete company cascades supervisors and properties.

7.2 Contractor
  - Save: duplicate Name rejected (case-sensitive DB check).
  - Delete by Id; not found → false.

7.3 Job catalog
  - ReplaceAll: replaces entire JobDescription table with provided list (used by
    Job Catalog page save). Null list rejected.

7.4 Invoice validation (data annotations + IValidatableObject)
  - Required fields per Invoice model.
  - Combined payments cannot exceed AmountCost.
  - Start Job / invoice workflows use ModelValidationService.Validate(model)
    returning OperationResult with first validation error message.

7.5 Accounts receivable payment application
  - User selects invoices via checkboxes; edits AmountPaid1/2, dates, check numbers.
  - "Done" applies payments via InvoiceDashboardService.ApplyReceivablePaymentsAsync:
      For each selected invoice: if AmountPaid1+AmountPaid2 > AmountCost → fail entire
      batch with message "The paid amount can not be greater than amount due!"
      Else update each invoice in DB.
  - Reports count of updated and "fully paid" invoices in success message.

7.6 Company / Property selection (Start Job)
  - Company name input is autocomplete (EditableDropdown) bound to company name list.
  - If the user types a company name that does NOT match any existing company:
      A Radzen Confirm dialog appears with:
        Title:   "Company Not Found"
        Message: "'{typed name}' was not found. Would you like to add it as a
                  new company?"
        Buttons: "Add Company" / "Cancel"
      If confirmed, CompanyService.EnsureCompanyByNameAsync is called which:
        - Trims the name
        - Allocates the next free CompanyID in 1000–9999 (linear scan)
        - Persists a new Company row
        - Returns the new entity
      The dropdown lists are augmented in memory with the new company.
      A success notification "'{name}' has been saved to the database." is shown.
  - Selecting an existing company loads its properties (via supervisors).
  - Selecting a property address auto-fills GateCode, LockBox, SpecialNote, and
    GarageRemoteCode on the form from the matching Properties record. Clearing
    the property selection clears these fields.

7.7 First-time database
  - On startup: EF migrations applied; EnsureDefaults creates an empty
    MyCompanyInfo row if none exists.
  - Removes known demo seed rows if no invoices exist (demo company/contractor
    names embedded in the seed data).

9. PAGE-BY-PAGE FUNCTIONAL SPECIFICATION
================================================================================

9.1 HOME (/)
  UI: EditForm with RadzenTextBox fields for MyCompanyInfo (Name, Phone, Email,
      Address, LicenseNumber, Zip). "Save Changes" submit button. ValidationSummary.
  Load: HomeWorkflowService.LoadAsync; on failure empty form + error toast.
  Save: validates required fields; success/error notification.

9.2 START JOB (/startjob)
  Section set: "Operations".
  Title: "Start Work Order" with description icon.
  TodaysDate defaults to today at component initialization.
  Form fields:
    - TodaysDate, WorkDate (RadzenDatePicker MM/dd/yyyy) required
    - Company Name: EditableDropdown over company names (case-insensitive
      StartsWith filter). Unknown name triggers the "company not found" flow
      (see §7.6).
    - Property Address: EditableDropdown (loads on company change)
    - Unit# required (RadzenTextBox)
    - BedroomSize, BathroomSize (RadzenNumeric)
    - Gate Code, Lock Box, Garage Remote Code, Work Order, Special Note
    - Job Description section: dynamic list of job type rows; each row has an
      EditableDropdown from the job catalog; "Add Another Option" button appends
      a row; per-row Remove button.
  Submit ("Submit" button) flow:
    1. SelectedJobTypes is built from each row's JobType string.
    2. StartJobWorkflowService.BuildDraftInvoice(request, jobs) builds a draft
       Invoice (Status = Draft, AmountCost = sum of catalog prices for selected
       job names). Validation failure shows an error notification and aborts.
    3. DialogService opens StartJobConfirmDialogComponent ("Job Confirmation")
       with the draft invoice as parameter.
    4. If the dialog returns true (Submit pressed inside the dialog), the page
       navigates to /createinvoice.
    5. If the dialog returns false (Cancel/Back), the user stays on Start Job
       with form state preserved.

9.3 ACTIVE JOBS (/activejobs)
  Filters: Start Date, End Date, Company dropdown (includes View All).
  Loads InvoiceDashboardService.LoadActiveAsync (Draft status).
  RadzenDataGrid: invoice columns (number, dates, company, address, amounts, etc.).
  Export buttons: PDF, Excel (see §12). Uses filtered invoice set.

9.4 CREATE INVOICE (/createinvoice)
  Section set: "Billing".
  Filters: Start Date, End Date (native <input type="date">); Submit button
  calls InvoiceWorkflowService.SearchInvoicesAsync and populates the grid.
  Grid: RadzenDataGrid of Draft invoices; columns Invoice Number (Id+10000),
  WorkDate (MM/dd/yyyy), Unit, CompanyName, PropertyAddress, AmountCost.
  RowSelect opens CreateInvoiceConfirmDialogComponent as a modal.
  Empty state: if hasSearched && no results → blue info alert "No draft
  invoices found in the selected date range. Start a new job to create a
  draft invoice."

  The "confirmation" dialog (/createinvoice-confirm-dialog) is a full editable
  form (EditForm + DataAnnotationsValidator) inside RadzenCard(s), not a
  read-only review:
    - Editable fields: TodaysDate, WorkDate (RadzenDatePicker), CompanyName,
      PropertyAddress, Unit, SizeBedroom/SizeBathroom (RadzenNumeric 0-10),
      WorkOrder, Contractor (EditableDropdown from active contractors only),
      SpecialNote, GateCode, LockBox, GarageRemoteCode.
    - Job Description section: deserializes JobDescriptionChoice JSON into
      editable list. For each line: RadzenTextBox (description) + RadzenNumeric
      (price, looked up from the jobs catalog passed as parameter by matching
      Description + SizeBedroom + SizeBathroom). Add/Remove buttons; price
      change triggers recalc of AmountCost.
    - AmountCost is also directly editable (RadzenNumeric).
    - Buttons: "Back" (DialogService.Close(false)), "Submit" (valid submit →
      InvoiceWorkflowService.SubmitInvoiceAsync(invoice, jobDescriptions list)
      which sets Status=Submitted, InvoiceCreatedDate=now, persists, returns
      success). On success the dialog closes with true and the parent navigates
      or refreshes.
  The jobs catalog and active contractor list are loaded by
  InvoiceWorkflowService.LoadCreateInvoicePageAsync and passed as parameters
  to the dialog.

9.5 ACCOUNTS RECEIVABLE (/accountsreceivable)
  Section set: "Finance".
  Filter: single Company dropdown (RadzenDropDown) including the "View All" option.
  Loading states are explicit in the UI:
    - "Loading accounts receivable..." (info alert) while isLoading
    - red danger alert if load fails (loadErrorMessage)
    - secondary alert "No receivable invoices match the current filters." if
      hasLoaded and the filtered list is empty
  Grid: receivable invoices (AmountCost > AmountPaid1 + AmountPaid2), paging
  size 10, sortable, column resize, column reorder.
  Columns include: Invoice Number, Work Date, Company Name, Amount Cost, a
  Select checkbox, "1st Payment" composite cell, "2nd Payment" composite cell,
  Special Note, Property Address, Unit, Gate Code, Lock Box, Bedrooms,
  Bathrooms, Work Order, Job Description, Contractor Name.
  Per-row Select checkbox toggles editability of the payment fields. When
  checked, the 1st / 2nd Payment cells render stacked RadzenNumeric (amount) +
  RadzenDatePicker (date, MM/dd/yyyy) + RadzenTextBox (check number).
  Buttons: Done (apply payments), Download to PDF, Download to Excel; all
  disabled while isLoading.
  "Done" calls InvoiceDashboardService.ApplyReceivablePaymentsAsync with the
  currently selected invoices (see §7.5 for batch validation rules).
  Column ordering is persisted to localStorage under the key
  "AccountReceivableColumnOrder" (comma-separated column titles); on load the
  grid restores the saved order when present.

9.6 AGING REPORTS (/agingreports)
  Data source: InvoiceService.GetInvoicesReceivable() (balance due > 0).
  Wrapper type exInvoice extends Invoice; on construct:
    DaysOverdue = (Today - (InvoiceCreatedDate ?? Today)).Days
  Filters:
    - Company dropdown (includes "View All")
    - Supervisor dropdown: when not View All, filter invoices where CompanyName
      matches the selected supervisor's parent Company.Name
    - Date range: when BOTH startDate and endDate set, filter WorkDate inclusive
  ApplyFilters rebuilds exInvoice list after each filter change.
  Grid columns: invoice #, WorkDate, Company, AmountCost, DaysOverdue, payments,
    property fields, job description, contractor, TodaysDate.
  Export PDF/Excel on filteredInvoices (PDF uses saveAsPDFFallback pattern).

9.7 SALES (/sales)
  Section set: "Finance".
  Filter row (4 columns): Start Date, End Date (RadzenDatePicker MM/dd/yyyy),
  Company dropdown, Address dropdown (Address list rebuilt when company changes).
  Loading states: info alert while loading; danger alert on error; secondary
  alert "No sales invoices match the current filters." when empty.
  Grid: submitted invoices (Status == Submitted), paging size 10, sortable,
  column reorder, column resize, default column width 140px.
  Columns include: a per-row Select checkbox, Invoice Number (Id+10000), Work
  Date (MM/dd/yyyy), Company, Property Address, Work Order, Price (AmountCost),
  Amount Paid1, Date Paid1, Amount Paid2, Date Paid2, Check Number, Unit,
  Bedrooms, Bathrooms, Job Description, Contractor Name.

12. CLIENT-SIDE REPORT GENERATION (PDF / EXCEL)
================================================================================

Loaded in wwwroot/index.html:

Libraries (loaded via CDN in wwwroot/index.html):
  - SheetJS xlsx 0.18.5 (full)
  - jsPDF 2.5.1 UMD + jspdf-autotable 3.5.25
  - html2pdf.js 0.9.2

Exposed window.* functions (must be callable from MAUI WebView / Blazor JS interop):

downloadFile(filename, content, contentType)
  - Creates Blob, triggers <a download>.

saveAsExcel(data)
  - data: array of plain objects with uniform keys.
  - Creates workbook with sheet name "Invoices"; writes "Invoices.xlsx".

setPdfData(data)
  - Stores the array on window.pdfData (used by fallback).

saveAsPDF(data)
  - Simple jsPDF + autoTable; title "Invoices"; columns from Object.keys of
    first row.

saveAsPDFByTemplate(templateID, filename, isLandscape=false)
  - Looks up element by id; if missing/empty → saveAsPDFFallback.
  - Uses html2pdf with: margin [10,10,10,10], jpeg quality 0.98, html2canvas
    scale=2, useCORS/allowTaint, a4 format (landscape or portrait), temp
    off-screen container sized to page.
  - On any error in the try block → falls back to saveAsPDFFallback.

saveAsPDFFallback(templateID, filename, isLandscape=false)
  - Requires window.pdfData (array of objects); alerts if missing.
  - jsPDF a4 (orientation per flag); title = filename (underscores → spaces,
    uppercased); timestamp line "Generated on: ..."; autoTable starting at Y=40.
  - Styles: fontSize 8, cellPadding 2; headStyles fillColor [41,128,185] white
    text; alternateRowStyles fillColor [245,245,245].
  - Saves as {filename}_fallback.pdf.

Blazor pages prepare export data as arrays of anonymous objects whose property
names become the table columns (matching visible grid columns, with formatted
invoice numbers, MM/dd/yyyy dates, etc.). Some pages (e.g. AR) always use the
data-based fallback path for reliability when the template element is not
guaranteed to be present or populated.

A legacy parseJwt helper exists in the same script block but is not used by
current business code.

13. APPLICATION UPDATE SYSTEM (GITHUB RELEASES)
================================================================================

Configuration is bound from the appsettings.json section named "UpdateSettings"
(the constant UpdateConfiguration.SectionName is "UpdateSettings"; not
"UpdateConfiguration"). Reference defaults shipped with the app:

  RepositoryOwner       "rattaroaz"
  RepositoryName        "DKSKMaui"
  RepositoryPath        derived as "{RepositoryOwner}/{RepositoryName}"
  Channel               "stable"
  IncludePreReleases    false
  CheckFrequency        Daily   (enum: Manual | Hourly | Daily | Weekly | Monthly)
  AutoDownload          false
  AutoInstall           false
  CheckOnStartup        true
  TimeoutSeconds        300
  BackupRetentionDays   7
  DownloadDirectory     "Updates"
  BackupDirectory       "Backups"
  GitHubToken           null   (optional, for private repos / rate limits)
  NotificationsEnabled  true
  PackagePattern        "*.zip"
  VerifyChecksums       true
  ChecksumFilePattern   "SHA256SUMS.txt"
  MaxRetryAttempts      3
  RetryDelaySeconds     5
  Enabled               true
  SourceMode            ReleaseOrPush   (enum: ReleaseOnly | PushOnly | ReleaseOrPush)
  UpdateBranch          "main"
  PushArtifactName      "dkskmaui-update-package"
  LastCheckTime         null   (runtime-updated)
  SkippedVersion        null   (runtime-updated when user skips a version)

IUpdateService state machine (enum UpdateState):
  Idle, CheckingForUpdates, UpdateAvailable, Downloading, Verifying,
  DownloadComplete, Installing, InstallComplete, RestartRequired, Error,
  RollingBack

UpdateInfo carries Version, CurrentVersion, SourceType ("release" | "push"),
BuildIdentifier, CommitSha, ReleaseDate, ReleaseNotes, DownloadUrl,
PackageSize, Checksum, IsMandatory, IsPreRelease, Channel, ReleaseName,
ReleaseId, AssetId, FileName. IsUpdateAvailable is true if either
Version > CurrentVersion OR BuildIdentifier differs from CurrentBuildIdentifier
(case-insensitive).

Flow:
  - On startup (if CheckOnStartup) the scheduler probes GitHub for a newer
    release/asset, or for a newer push artifact if SourceMode allows.
  - Download the release asset / push artifact with progress events
    (DownloadProgress with bytes, total, speed, percentage).
  - Optionally verify against the SHA256SUMS.txt sidecar (VerifyChecksums).
  - Install to the application directory; may invoke ApplicationRestartService
    to restart the app after install.
  - On install failure, RollbackAsync restores from the timestamped backup
    folder under BackupDirectory (kept BackupRetentionDays days).
  - UpdateAnalyticsService persists a local statistics file (checks attempted,
    downloads completed, installs completed, failures).
  - Push mode: when SourceMode includes Push, BackgroundDownloadService and
    UpdateCacheService pre-fetch the artifact named PushArtifactName from the
    given UpdateBranch.

UI surfaces:
  - /settings/updates  — current version, check-for-updates, configuration
  - /settings/updates/dashboard — live progress, history, install / rollback
  - Optional UpdateNotification banner shown when an update is available

14. PERSISTENCE, STARTUP, AND CONFIGURATION
================================================================================

Startup sequence (conceptual):
  1. Configure SQLite compatibility switch for .NET 10 DateTime handling.
  2. Load appsettings.json from the app base directory if present. The only
     business-relevant section is "UpdateSettings" (see §13); the "Serilog"
     and "Logging" sections are intentionally out of scope for this document.
  3. Register all DI services. Reference lifetimes:
       Singleton: GlobalStateService, IUpdateService and all update helpers,
                  ApplicationRestartService.
       Scoped:    All page-facing services (CompanyService, InvoiceService,
                  InvoiceDashboardService, InvoiceWorkflowService,
                  InvoicePresentationService, StartJobWorkflowService,
                  HomeWorkflowService, ContractorService, PropertiesService,
                  SupervisorService, JobDescriptionService, MyCompanyInfoService,
                  ImportExportService, ModelValidationService).
       DbContext: AppDbContext scoped, SQLite provider.
  4. Build the MAUI app with a BlazorWebView pointed at the Blazor Components
     root.
  5. DatabaseStartup.InitializeDatabase:
       - Apply EF Core migrations.
       - Ensure the unique CompanyID column / index exists on legacy databases
         that predate the schema change.
       - ApplicationDataInitializationService.EnsureDefaultsAsync inserts a
         placeholder MyCompanyInfo row if none exists and prunes known demo
         seed rows when the Invoice table is empty.
  6. Register update services and run an optional startup update check when
     UpdateSettings.CheckOnStartup = true.

Database file path: {LocalApplicationData}/DKSKMaui/Database/app.db
Legacy migration: if an older app.db exists under the app base directory's
"Database" folder and the new LocalApplicationData path has no DB yet, the
file is copied to the new location and the old file is renamed with a
".backup" suffix.

EF Core configuration in OnModelCreating:
  - Unique index on Company.CompanyID.
  - Supervisor.Company → Company (one-to-many, cascade delete).
  - Properties.Supervisor → Supervisor (one-to-many, cascade delete).
  - DbSet aliases: Companies → Company, JobDescriptions → JobDescription
    (lets code use either name).
